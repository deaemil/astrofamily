# Астро Атлас

Лична база с натални карти и сравнение на един човек с няколко близки. Интерфейсът е изцяло на български. Приложението започва с празна база — няма примерни хора, измислени позиции или оценки за съвместимост.

## Стартиране

Изисквания: Node.js 22.12+ (проверено с 24.19), Python 3.12, GCC и G++ за компилиране на pyswisseph. Използвайте съществуващото хранилище; средата вече е изолирана и не изисква Git worktree.

```bash
cd /workspace/astrofamily
bash scripts/install.sh
npm run dev
```

Инсталацията използва package-lock.json, фиксираните Python зависимости и официалните Swiss Ephemeris файлове за периода 1800–2399. Файловете се изтеглят чрез HTTPS от фиксиран commit и се сверяват със SHA-256 в `server/ephemeris-manifest.json`. При повторно изпълнение валидните файлове се използват отново. Кешовете са в `/workspace`, тъй като домашната директория на cloud средата не е записваема.

Стартират Vite на порт 5173 и FastAPI на порт 8000. Vite препраща `/api` към FastAPI. `scripts/dev.sh` спира собствените си процеси при изход. Процесите трябва да бъдат стартирани отново в нова облачна задача. Проверка на работещите услуги (вътрешни заявки):

```bash
curl --fail http://127.0.0.1:5173/
curl --fail http://127.0.0.1:8000/api/health
```

За продукционна сборка:

```bash
npm run build
.venv/bin/python -m uvicorn server.main:app --host 0.0.0.0 --port 8000 --no-access-log
```

FastAPI обслужва `dist` след build, включително SPA fallback. При продукционен хостинг използвайте HTTPS и подходящ обратен прокси. Няма външни шрифтове — шрифтовете са локални.

## Supabase: постоянна база и вход с имейл

Без конфигурация работи ясно обозначен **локален режим** с localStorage. Той е за един браузър, няма потребителска изолация между хората, използващи същия браузърен профил, и не осигурява облачен архив. Реалните изчисления и ръчните карти работят и в този режим.

За постоянна лична база:

1. Създайте Supabase проект и изпълнете `supabase/schema.sql` в SQL Editor.
2. Активирайте Email provider в Authentication. При включено потвърждение потребителят трябва да потвърди имейла си. Задайте Site URL и допустимите redirect адреси за вашия домейн.
3. Задайте `SUPABASE_URL` и **публичния publishable/anon ключ** като `SUPABASE_ANON_KEY` в настройките на средата или в локален `.env` (виж `.env.example`). Никога не използвайте `service_role`/secret ключ. Такъв ключ се отхвърля от `/api/config`.
4. Рестартирайте FastAPI. В приложението изберете „Вход с имейл“ → „Създай акаунт“ или „Вход“.

Таблицата `atlas_documents` пази един JSON документ с хора, карти и настройки за всеки `owner_id`. RLS е включен и принудително активиран; всички операции са ограничени с `auth.uid() = owner_id`. Анонимната роля няма достъп. Няма споделяне и service_role ключ не е необходим. Публичният anon ключ е предназначен за браузъра; достъпът се защитава от RLS и потребителската сесия.

Локалният и облачният атлас са отделни. Данните не се качват автоматично при вход. За прехвърляне изтеглете JSON архив, влезте и го възстановете в облачния акаунт. При грешка в зареждането записът се блокира, за да не се презапише съществуващият атлас с празна база. Облачните записи се потвърждават преди показване на „Запазено“. При едновременна редакция от няколко устройства последният успешен запис на целия атлас има предимство.

В текущата среда няма Supabase проект/ключове: реалният облачен вход и интеграцията с отдалечен проект остават непроверени. Самите RLS политики се изпълняват в тест с истински PostgreSQL двигател (PGlite) и симулирана Supabase identity функция.

## Изчислителен модел

- Swiss Ephemeris 2.10.03 чрез `pyswisseph`, на сървъра. Няма LLM изчисления или случайни стойности. Пътят до ефемеридите се задава във всяка работна нишка.
- Тропически, геоцентрични позиции; Placidus / Whole Sign / Equal House; истински или среден лунен възел. Лилит е **среден лунен апогей**.
- 20 точки: Слънце, Луна, Меркурий, Венера, Марс, Юпитер, Сатурн, Уран, Нептун, Плутон, Хирон, Лилит, двата възела, ASC, DSC, MC, IC, Вертекс и Фортуна.
- Фортуна: ASC + Луна − Слънце денем; ASC + Слънце − Луна нощем. Ден/нощ се определя по истинската височина на Слънцето над хоризонта.
- Домът е определен по еклиптичната дължина между последователните куспиди. Използваният метод и настройките се пазят с картата.
- Часовата зона се намира по координати с timezonefinder. Историческите правила и DST са от IANA чрез pytz. Двусмислените и несъществуващите местни часове изискват корекция; текущото UTC отместване не се използва за минали дати. Позволени са проверена IANA зона и ръчно отместване в минути. Много старите времена зависят от историческата пълнота на IANA.
- Без точен час се използва ясно обозначено местно 12:00. Не се дават домове/ъгли/Вертекс/Фортуна; има диапазон на Луната от началото до края на местното денонощие, включително при DST в полунощ. Всички условни позиции са изключени от сравненията по подразбиране.
- Приблизителният час маркира позициите и домовете като приблизителни. Ръчните корекции в автоматична карта не отменят несигурността на неизвестния час.
- Placidus при полярни ширини връща конкретна грешка и изисква изричен избор на друга система. Няма автоматично заместване.
- За дати извън наличния файлов интервал Swiss Ephemeris може да използва аналитичния Moshier модел. Това се посочва в източника и предупреждението. Точки без нужния файл (напр. Хирон) са „Не е налична“.
- Пълната числова точност се пази в JSON; закръгляне се прави само за показване. Промяна на рождените данни със запис без изчисление или промяна на изчислителните настройки маркира картата като остаряла. Старите изчислени позиции се изключват от карти, аспекти и повторения до успешно преизчисление. Ръчните корекции са отделни и оригиналите могат да се възстановят.

## Места и мрежа

Вграден е офлайн GeoNames каталог с над 32 000 реални града, координати и IANA зони, както и български имена за основните градове. Поддържат се алтернативни изписвания. Държавите се показват на български. За по-малки населени места се опитва Open-Meteo Geocoding API; при недостъпност има ясно съобщение и ръчно въвеждане на координати.

Необходими дестинации за инсталация: `registry.npmjs.org`, `pypi.org`, `files.pythonhosted.org`, `raw.githubusercontent.com`. Допълнително онлайн търсене: `geocoding-api.open-meteo.com`. Supabase браузърът се свързва директно с URL на вашия проект. Ако мрежовата политика ограничава този трафик, разрешете точния домейн на проекта. Не се изискват астрологични API ключове.

## Импорт и експорт

CSV импортът има съпоставяне на колони, преглед преди запис, грешки по редове и избор „пропусни/обнови“ дубликатите. При повторение в самия файл „пропусни“ запазва първия ред, „обнови“ — последния. Не се импортира нищо, докато има грешки. При повече от един съществуващ човек с едно и също име импортът изисква имената да бъдат разграничени.

Пример (това е формат за импорт, **не** предварително заредена карта):

```csv
Име,Точка,Знак,Градуси,Минути,Ретроградност,Дом,Статус,Бележка
Име на човек,Луна,Лъв,0,0,Не,,Потвърдена,Вашият източник
```

Празният градус е липсваща позиция, не 0°. Празни минути означават 0 за приблизително сравнение с маркер. Статус „За проверка“ е изключен по подразбиране. Експортът на позиции е в профила, а на аспекти — в таблиците. CSV стойности, които могат да се интерпретират като формули, се екранират. JSON архивът пази пълната точност и се валидира преди потвърдено заместване на атласа.

## Проверки

```bash
npm test                    # 18 математически/данни + 5 RLS теста
npm run test:server         # реални позиции, DST, домове, неизвестен час, градове
npm run build               # TypeScript и production bundle
npx playwright test         # стартирайте npm run dev предварително
```

Playwright използва инсталирания `/usr/bin/chromium` (или `CHROMIUM_PATH`). Тестовите карти се създават само в изолирани браузърни контексти и не попълват реалния атлас. Проверяват се CRUD, 0°/празни стойности, сравнение с няколко души, граничен орбис, приблизителни данни, CSV и архив, повторения, реални ефемериди, преизчисление, reload и мобилен изглед. За реален Supabase проект трябва допълнително да се проверят регистрация, потвърждение на имейл и работа на два отделни акаунта след задаване на конфигурацията.
